# Работа с проектом

## Перед изменениями

Используйте Node.js 24 из `.nvmrc` и `npm ci`. Сайт полностью статический: для разработки не нужны аккаунты, API-ключи, база данных или `.env`.

Код и имена коммитов — на английском; текст интерфейса и основная документация — на русском.

## Проверки перед pull request

```sh
npm run format
npm run check
npm run build -- --base=/kedr-01/
```

Затем прогоните браузерные тесты production-сборки по инструкции в [README](README.md#github-pages). Для локальных тестов нужен Google Chrome; они используют отдельный headless-профиль.

Если меняется интерфейс, проверьте desktop и mobile, навигацию с клавиатуры, Escape в диалогах и режим уменьшенного движения. `node scripts/visual-check.mjs URL` сохраняет контрольные снимки в `output/site-qa/`.

## Важные договорённости

- Не добавляйте в Git секреты, сырые генерации, PDF с рабочим контекстом, тестовые отчёты, `node_modules/` или `dist/`.
- Не публикуйте неподтверждённые технические характеристики аппарата. Это художественный концепт.
- Новые зависимости добавляйте с точной версией (`npm install --save-exact` или `--save-dev --save-exact`) и обновляйте lock-файл вместе с `package.json`.
- Учитывайте `import.meta.env.BASE_URL` для динамических ссылок на медиа; корневой `/media/` не работает на project Pages.
- При замене анимации синхронно обновляйте desktop/mobile кадры, `FRAME_COUNT`, проверку медиа и тесты. Сохраняйте постер и reduced-motion fallback.
- Не добавляйте отправку данных или аналитику без отдельного согласования.

Pull request проходит проверки без публикации. Деплой выполняется после успешных проверок ветки `main`.
